# 실험 규칙

## 폴더 이름
- `P###_이름/` — 이 저장소 이전에 수행된 실험의 근거 자료(읽기 전용, 바이트 그대로 보존). 파일 이름은 아래 규칙이 아니라 원래 실험의 이름을 따를 수 있으며, 각 폴더의 `README.md`가 대응을 설명한다.
- `E###_이름/` — 이 저장소에서 수행하는 실험. 번호는 로드맵 단계를 따른다(E001 = 단계 B, E002 = 단계 C, E01x = 단계 D, E02x = 단계 E, E1xx = 단계 F).

## 실험 폴더에 들어가는 것
| 파일 | 언제 | 내용 |
|---|---|---|
| `PLAN.md` | 실행 전 | 질문, 바꾸는 것 하나, 고정 조건, 셀과 seed, 측정 지표, 채택 문턱, 판정 규칙. 실행 뒤에는 고치지 않고, 바뀐 점은 맨 아래 변경 기록에 시각·이유와 함께 덧붙인다. |
| `PLAN.sha256` | 실행 전 | `PLAN.md` 고정본의 해시 |
| `config.yaml` | 실행 전 | 실행 설정(경로는 논리 이름만) |
| `results/` | 실행 후 | seed별 원자료 CSV, 집계 CSV/JSON(작은 파일만) |
| `REPORT.md` | 실행 후 | 결과, 판정, 한계, 다음 단계 |
| `logs/` | 실행 중 | 원본 로그. git에 올리지 않음(`.gitignore`) |

## 규칙
1. **시험셋.** 단계 F 전에는 어떤 실험도 시험셋을 읽지 않는다. 단계 F는 별도 사전등록 후 한 번만 읽는다.
2. **선택.** 체크포인트·헤드·임계값·하이퍼파라미터는 검증 분할로만 고른다.
3. **seed.** 개발 seed(0, 1, 2)와 확정 seed(10개)를 섞지 않는다.
4. **실패 기록.**
   - 실패하거나 중단한 실행은 보고서에 횟수와 이유를 적는다.
   - 실행 상태 요약(작은 CSV/JSON)은 `results/`에 넣는다.
   - 원본 로그는 git 밖(`logs/`나 서버)에 두고, 보고서에 위치를 적는다.
5. **판정 규칙 고정.** 결과를 본 뒤 판정 규칙을 바꾸지 않는다.
